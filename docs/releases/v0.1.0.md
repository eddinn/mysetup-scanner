The first release of the MySetup scan scripts. Each prints a text report of your computer's hardware: CPU, graphics, motherboard,
memory and storage. You read it, then paste it into the Hardware section of your build on [MySetup](https://mysetup.is), where you
review every part before anything is saved. Parts from a report are marked "Detected".

The scripts only read. They use no network, write no files, install nothing and do not ask for root unless you say so.

## Files

| File | For |
|---|---|
| `mysetup-scan.sh` | Linux, macOS, the BSDs and other Unix-like systems: `sh mysetup-scan.sh` |
| `mysetup-scan.ps1` | Windows, in PowerShell: `powershell -ExecutionPolicy Bypass -File .\mysetup-scan.ps1` |
| `SHA256SUMS` | Checksums of both |

MySetup's build page serves the same two files, with the same checksums.

## Check a download

Compare it with the checksums:

```sh
sha256sum -c SHA256SUMS --ignore-missing
```

Or check GitHub's attestation, which records that the file was built from this repository at this tag:

```sh
gh attestation verify mysetup-scan.sh --repo eddinn/mysetup-scanner
```

The scripts are not code-signed. Windows blocks unsigned scripts from the internet by default; `-ExecutionPolicy Bypass` lifts that
for one run and changes no setting.

## Where it has been tested

Tested on real machines: Windows x86-64 (PowerShell 5.1, without admin rights) and Linux x86-64 with systemd (Debian 13, without
root). On other systems the scripts run, but say "untested on this system", and the report says `tested=no`: please check such a
report before you paste it, and tell us how it went. In a virtual machine or a container a report says so; inside WSL the script
sends you to the Windows script.

The scripts also ran cleanly on GitHub's Linux, Windows and macOS runners and in containers of Alpine, Debian, Ubuntu, Fedora,
Rocky, Arch, openSUSE and Void. That shows they run there and print a valid report, not that real hardware reads correctly.

## What a report never contains

Usernames, hostnames, IP or MAC addresses, motherboard or system UUIDs, machine GUIDs, Windows SIDs, product keys, disk serial
numbers, file paths, file names, network names or other software. The report format is in
[docs/report-format.md](https://github.com/eddinn/mysetup-scanner/blob/v0.1.0/docs/report-format.md).
